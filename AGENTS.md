# AGENTS.md — Meridian

**Meridian** — планувальник харчування для сім'ї. Бере плани дієтолога (PDF),
розкладає їх на страви й сам збирає раціон на тиждень: тримає калорійність і
структуру дієтолога, але міксує страви з кількох планів. Терміни — у
[`GLOSSARY.md`](GLOSSARY.md).

Цей файл — карта репозиторію й тверді правила. Нюанси шарів живуть у README
їхніх тек. Стан проєкту, робочий процес (гілки, PR, статуси) і граблі
середовища — у Linear-документі
[**AGENTS · Онбординг — почни звідси**](https://linear.app/meridian-ua/document/agents-onbording-pochni-zvidsi-3e4042ac2e4a);
задачі — у [проєкті Meridian](https://linear.app/meridian-ua/project/meridian-b257f2e0b2df)
(команда `MER`).

## Правило документації

- **Перед зміною файлу прочитай `README.md` найближчої теки вгору** (у `infra`
  ще й `DECISIONS.md`). Там правила шару, які не видно з коду.
- **Нюанс модуля пишеш у `README.md` його теки**, під заголовком з **ім'ям
  експорту** (`### saveWeek`), щоб `grep` знаходив і код, і нюанс. Інваріант —
  у тест із назвою-реченням; те, що виражається іменем чи типом, — в ім'я чи
  тип. README теки — не більше ~12 тис. символів.
- **Коментарів у коді не пишемо** (рішення власника): код читають і пишуть лише
  агенти. Лишаються директиви інструментів (`@ts-check`, `/// <reference>`,
  `eslint-disable … -- причина`, `@ts-expect-error`, шебанг,
  `# yaml-language-server:`, `# syntax=`). Винятки для людини, що хостить
  сама: `.env.example`, шаблони issue й PR. Застосовані міграції `0000–0007`
  заморожені як історія; нові міграції — без коментарів, пояснення рядком у
  таблиці міграцій `packages/db/README.md`. Храповик — `tools/check-comments.mjs`
  і `eslint.config.base.mjs`.
- **Спрощення з відомою межею (`ponytail:`) — у README теки** під
  `## Відомі стелі (ponytail)`: що спрощено, межа, шлях апгрейду. Не в код.
- **Змінив `README.md` у корені — перепиши `README.en.md`** у тому ж PR:
  українська версія основна, англійська — її переклад.
- Змінив шлях, назву чи правило, на яке посилається онбординг у Linear, —
  онови його в тій самій задачі.

`pnpm lint && pnpm typecheck && pnpm test && pnpm format:check && pnpm build`.

**Стек V2 (local-first).** Джерело істини для інтерфейсу — SQLite на пристрої;
PowerSync фоном синхронізує його з Postgres; записи йдуть через PostgREST
(LWW на рівні рядка, без CRDT). Сервер — підмножина self-host Supabase
(Postgres, GoTrue, PostgREST) за Caddy в одному `compose.yaml`. Сервера
застосунку немає. Обґрунтування — [ADR 001](https://linear.app/meridian-ua/document/adr-001-arhitektura-meridian-v2-224108dca97d),
таблиці — [ER-схема](https://linear.app/meridian-ua/document/v2-er-shema-bd-mer-44-mer-55-mer-45-9e855efdb7ab).
V1 (один HTML на `main`) видалено з `staging` у MER-68 — шукати в історії git.

**Модель даних** описують `packages/core/src/types.ts` і міграції
`packages/db/migrations`, а не цей файл.

## Перехресні інваріанти

Правила, що не належать одній теці:

- **Один claim тримає все.** `family_id` у JWT кладе хук доступу GoTrue
  (`compose.yaml`), на ньому стоять RLS (`public.current_family_id()`) і стріми
  PowerSync (`auth.parameter('family_id')`). Немає claim — порожньо й без
  помилок.
- **Синхронна таблиця змінюється в чотирьох місцях разом:** міграція
  (публікація `powersync`, `GRANT SELECT` для `powersync_role`),
  `infra/powersync/sync-config.yaml`, `AppSchema` і
  `JSON_COLUMNS`/`BOOLEAN_COLUMNS`. Розбіжність ловить
  `apps/web/src/lib/powersync/sync-contract.test.ts`.
- **Видалення — це `deleted_at`.** Фізичного DELETE немає ні в коді, ні в
  правах; у кожній вибірці sync — `deleted_at IS NULL`.
- **Рядок під частковим унікальним індексом створюється з виведеним id**
  (`packages/core/src/sync-ids.ts`), а шукається за природним ключем.
- **Стан пристрою не синхронізується:** активний профіль, охоплення списку
  покупок, нагадування (рішення MER-55, `packages/db/README.md`).
- **`PUBLIC_*` береться рантаймом** — Caddy вписує його в `index.html`. Під час
  збірки веб-образу `PUBLIC_*` не задавати (`apps/web/README.md`).

## Тверді правила

### Мова й залежності

- **Мова інтерфейсу — українська.** Уся копірайтинг-частина, підписи,
  повідомлення. Калорії — ккал, БЖВ — грами.
- **Жодних російських залежностей, сервісів чи джерел** — ні бібліотек, ні API,
  ні шрифтів російського походження.
- **Класичні, перевірені рішення й простий код.** Нова залежність — лише коли
  без неї ніяк, з обґрунтуванням у PR; postinstall — через `allowBuilds` у
  `pnpm-workspace.yaml`.
- **Конфіги й API звіряються з офіційною документацією**, а не пишуться з
  пам'яті. Розбіжність з інструкцією фіксується в README теки.

### Провенанс даних

Кожне поле кожної страви й рецепта береться **лише** з одного з трьох джерел:
(1) плану дієтолога, (2) імпорту з цього PDF, (3) ручного вводу користувача,
який переписує зі свого джерела.

Застосунок **ніколи не генерує, не вгадує й не доповнює** значень: назви,
калорії, БЖВ, інгредієнти, кількості, кроки, час, порції, фото. Немає в
джерелі — поле порожнє, а секція UI ховається. Жодних «приблизних», «типових»
чи «схожих» значень. Порожнє — `null`, а не нуль: нуль — це справжній нуль.

**Виняток лише для калорій.** На них тримається коридор генератора, а частина
планів їх не дає. Тому калорійність страви зі стартового набору може бути
оцінкою з загальних таблиць харчування — лише з `caloriesApprox: true` і
префіксом «≈» в UI. Ручний ввід і імпорт із PDF «≈» не ставлять, а правка
калорійності позначку знімає. Очевидні описки в плані виправляються,
а розбіжності в цифрах лишаються як є й описуються в `sourceIssues`. Те саме правило — для роботи агента: не
вигадувати полів, API й команд.

### Приватність і PII

Застосунок зберігає чутливі дані сімей, тож усе, що створюють агенти, — код,
demo- і seed-дані, README, коміти, PR, задачі й документи Linear — лишається
**generic** і не прив'язане до жодної реальної людини, включно з власником.

- Ніяких реальних імен, email, телефонів, адрес. Приклади вигадані
  (`user@example.com`, «Користувач 1», «Дитина 1»).
- Задачі й PR описують проблему й рішення generic-мовою («користувач», «профіль
  сім'ї»); коміти — суто технічно.
- **Плани дієтолога й справжній стартовий набір у репозиторій не потрапляють
  ніколи** — ні файлом, ні фікстурою, ні прикладом. У репозиторії лише
  вигаданий `infra/starter-set.example.json`.
- Правило передається суб-агентам у промпті.
- Виняток — технічні поля, де ідентифікація власника потрібна за домовленістю
  (`LICENSE`, `package.json.author`, git-конфіг).

### Стилі

**Tailwind — без arbitrary values.** Не писати `py-[7px]`, `text-[13px]`,
`rounded-[10px]` і не відтворювати їх «точність» дробовими класами на кшталт
`py-1.75`. Брати найближчий токен зі стандартної шкали (`py-2`, `text-sm`,
`rounded-xl`). Arbitrary variants (`[&.active]`, `[&_input]`) дозволені: це
селектори, а не значення. Значення, яке не можна округлити без втрати
поведінки (safe area, колір профілю, точний breakpoint), — семантичний
іменований токен у `@theme` (`apps/web/src/styles.css`). Решта правил
дизайну — `apps/web/src/components/README.md`.

### Репозиторій

- **Кінці рядків — LF скрізь** (`.gitattributes`: `* text=auto eol=lf`). Не
  додавати `core.autocrlf`.
- **`.prettierignore` — шляхи повністю.** Патерни без якоря: голе `data/`
  сховало б і `apps/web/src/lib/data/`.
- **ESLint спільний:** правила — `eslint.config.base.mjs` у корені, `eslint.config.js`
  пакета лише розгортає базу й додає свій `ignores` (MER-71). Prettier —
  `prettier.config.mjs` у корені.
- Один менеджер пакетів — pnpm (`pnpm-lock.yaml`).
