# i18n — мова інтерфейсу

Українська — основна мова й джерело всіх текстів, англійська — переклад
(MER-121, ч. 1 — MER-127). Нової залежності немає: словники — звичайні
об'єкти TypeScript, множини й формати — `Intl`.

| Модуль | Що |
|--------|-----|
| `uk.ts` | Український словник; його форма — тип `Messages` |
| `en.ts` | Англійський словник, оголошений як `Messages` |
| `locale.ts` | Вибрана мова пристрою, `messages()`, `intlLocale()`, `pickLocale` |
| `use-messages.ts` | `useMessages()` / `useLocale()` для компонентів |
| `rich-text.tsx` | `RichText`: рядок словника з елементами всередині |

## Правила

- **Новий рядок UI — одразу в обидва словники.** `uk` задає ключі й
  сигнатури, `en` оголошено як `Messages`, тож пропущений ключ валить
  `typecheck`. Кирилиця поза словниками й тестами в `apps/web/src` — лише
  порційні літери Ж/Ч: це ключі даних плану (`nutrition.Ч`), а не текст.
- **Текст із числом — функція словника**, а не склейка в компоненті: порядок
  слів і множини в мовах різні. Множини кожен словник рахує своїм
  `Intl.PluralRules` (в uk — одна/кілька/багато, в en — одна/інші).
- **Рядок з елементом усередині** (`<code>`, ім'я файлу) — плейсхолдер
  `{name}` і `RichText`, а не шматки речення в JSX.
- **Компонент бере тексти з `useMessages()`** — він підписаний на мову й
  перемальовується одразу після перемикання. Модулі без React (`messages.ts`,
  `forms.ts`, `format.ts`, `day-clock.ts`, `reminders.ts`) читають
  `messages()` у момент виклику; їх кличуть компоненти, що вже підписані.
- **Коди ядра — у текст лише через словник.** Генератор і заміна віддають
  коди (`GenerateFailure`, `WeekWarning`, `SlotFailure`, `SwapReason`);
  текст — `week.failure`, `week.warning`, `week.poolShortage`,
  `swap.failure`, `swap.reason`. `switch` за `code` з типом повернення
  `string`: новий код у ядрі без гілки в кожному словнику валить
  `typecheck`. Українські тексти дослівно ті, що були в ядрі, —
  `core-messages.test.ts`.
- **У стані тримати ключ, а не текст**, якщо його видно довго (відмова в
  дозволі на сповіщення — `Refusal`), інакше після перемикання лишиться стара
  мова.
- Дати й числа — `intlLocale()` (`uk-UA`, `en-GB`), не літерал локалі. Одиниця
  калорій іде в ядро параметром `unit` (`formatCalories` і сусіди), правила
  «≈» і «чи показувати» лишаються в ядрі. `meal-text.ts` і `meals-search.ts`
  свідомо лишають `uk-UA`: текст форми розбирається назад, а пошук
  нормалізує українські назви страв.
- Контент не перекладається: назви страв, рецепти, плани, дані сім'ї. Зразки
  тексту плану (`День 1`, `Сніданок: …`) лишаються українськими й в `en` —
  розбирач читає саме їх.

## locale.ts

- **Вибір — стан пристрою** (`localStorage`, `meridian.locale.v2`), як і
  інші налаштування за рішенням MER-55; у синхронізацію не їде. Перемикач —
  на екрані «Сім'я» (`LanguagePanel`).
- **Початкова мова — `pickLocale(navigator.languages)`**: перша підтримувана
  за основним підтегом, інакше українська. `ru` — псевдонім української:
  браузер із `ru` першим отримує українську, а не наступну мову списку.
- `applyLocale` ставить `<html lang>` до першого кадру (`main.tsx`) і після
  кожного `setLocale`; сповіщення беруть `lang` з `getLocale()`.
- Поза браузером (`node --test`) мова — українська, тож тести модулів без
  React перевіряють український текст.

## Відомі стелі (ponytail)

- **Тексти розбору PDF, перенесення V1 й перевірки стартового набору ще
  українські** (`packages/core`): MER-128 перевів на коди лише генератор і
  заміну. Шлях — той самий: коди з параметрами й гілка в словниках.
- **Плани, згенеровані до MER-128,** тримають у `week_plan.warnings` готовий
  український текст — `planWarnings` віддає його як є, до перегенерації
  тижня. Мігрувати не варто: V2 ще не випущено, такі плани є лише в
  тестових стеках.
- **Помилка, вже показана в стані** (`Failure`), лишається мовою моменту
  дії — до наступної дії.
- Маніфест PWA і `index.html` (заголовок, опис) — один на збірку, українські.
- Польська й німецька — MER-129: новий словник і рядок у `LOCALES`.
