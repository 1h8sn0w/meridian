# lib — логіка застосунку поза екранами

Доменної логіки тут немає: генератор, калорії й провенанс живуть у
[`packages/core`](../../../../packages/core/README.md). Тут те, що належить
пристрою й браузеру. Підтеки мають свої README:
[`data`](data/README.md) (читання й записи бази) і
[`powersync`](powersync/README.md) (синхронізація).

| Модуль | Що |
|--------|-----|
| `auth.tsx` | Стан входу й сім'ї: сесія GoTrue, claim `family_id` |
| `supabase.ts` | Один клієнт Supabase на вкладку |
| `public-env.ts` | Публічний конфіг рантаймом (`apps/web/README.md`) |
| `day-clock.ts` | Вікна прийомів їжі, їх валідація й геометрія годинника дня |
| `meal-windows.tsx` | Вікна сім'ї з `family_settings` для всього застосунку (`useMealWindows`) |
| `use-now.ts` | Одне «зараз» на весь застосунок |
| `reminders.ts` | Нагадування перед прийомами: розклад, текст, налаштування |
| `starter-set.ts` | RPC стартового набору й порядок кроків засіву |
| `pdf-text.ts` | Текстовий шар PDF через pdf.js |
| `active-profile.ts`, `shopping-scope.ts`, `device-choice.ts` | Вибір, що належить пристрою, а не сім'ї |
| `forms.ts` | Чернетки й валідація форм (MER-103) |
| `format.ts`, `messages.ts`, `meal-text.ts` | Підписи, помилки українською, інгредієнти й порції ↔ текст форми |
| `calendar-search.ts`, `meals-search.ts` | Стан «Календаря» й фільтри «Страв» в адресі |
| `shopping-share.ts` | Список покупок текстом (MER-85) |
| `scroll-catch-up.ts` | Догнати прокрутку, яку роутер не встиг відновити (MER-86) |
| `wake-lock.ts` | Екран не гасне, поки відкрито рецепт (MER-119) |

Модулі без React (`reminders.ts`, `day-clock.ts`, `messages.ts`, …) імпортують
сусідів із `.ts`: так їх бачить `node --test`, що стирає типи, але не
переписує шляхів. Публічний конфіг (`public-env.ts`) — у
[`apps/web/README.md`](../../README.md#публічний-конфіг-береться-рантаймом-mer-45).

## Вибір пристрою

`useStoredChoice` (`device-choice.ts`) — сховище в `localStorage`, читається
синхронно до першого рендеру; `null` стирає ключ, щоб сентинел не лежав
рядком поруч з id. Самозцілення в кожного своє:

- **`useActiveProfile`**: збережений id зник (профіль видалили на іншому
  пристрої) — перший профіль, і це **записується**, щоб пережити
  перезавантаження. `applyAccent` ставить лише `--accent`; прозорий варіант —
  `color-mix` у CSS. `ownerCorridorApplies` — порція профілю збігається з
  порцією власника плану, тож коридор плану про його цифри (MER-79).
- **`useShoppingScope`**: зниклий профіль — «усі», і це **не записується**:
  «усі» — це відсутність ключа. Краще показати більше, ніж нічого.
- `useNow` — одне «зараз» на застосунок, такт 30 с, є вже з першого кадру.

## auth.tsx

**Сесія живе на пристрої, а сервера застосунку немає взагалі.** Вхід робить
браузер через `@supabase/supabase-js`. До першої відповіді GoTrue стан входу —
`loading`, і вгадувати користувача нікому. Стан входу перевіряється один раз у
кореневому маршруті (`components/AppGate.tsx`), і лише стан «увійшли й сім'я
є» пускає до маршрутів застосунку (MER-49).

- **Після зміни членства обов'язковий `refreshSession()`.** Старий токен ще без
  claim `family_id`, і застосунок бачитиме порожньо.
- `onAuthStateChange` сам віддає `INITIAL_SESSION`, окремий `getSession()` не
  потрібен; у колбеку — лише `setState` (вимога документації Supabase).
- Сім'я, склад і запрошення читаються без фільтра `family_id`: вибірку звужує
  RLS. Відповіді для сім'ї, що встигла змінитись, відкидаються.
- `signUp` → `false`: сесії немає, GoTrue чекає підтвердження пошти. Термін
  запрошення береться з бази, а не рахується тут.
- **Запрошення — кодом, не листом.** Self-host без SMTP листа не надішле, а
  обіцяти в інтерфейсі те, чого не буде, не можна. Правила БД для членства —
  [`packages/db/README.md`](../../../../packages/db/README.md).

## supabase.ts

Один клієнт на вкладку: другий незалежно оновлював би той самий
refresh-токен. Сесія — у `localStorage` (типово для supabase-js; так само у
WebView Capacitor), `detectSessionInUrl: false` — OAuth і посилань немає.
`familyIdFromToken` читає claim без перевірки підпису: це підказка
інтерфейсу, доступ вирішує Postgres.

## messages.ts

Перекладаємо те, що людина може виправити; решту — загальний текст плюс
оригінал, без якого той, хто піднімав self-host, не має з чого почати. Правила
`localDbFailure` і `syncFailure` — у `messages.test.ts`: помилки PowerSync
приходять із воркера лише текстом, тож мережа й «вхід не прийнято»
впізнаються регулярками за текстами браузерів. `Outcome` — свій тип, не
`Result` ядра: два різні типи під одним іменем — пастка.

## format.ts, meal-text.ts

- «Чи показувати» й «≈» вирішує ядро (`formatCalories`, `hasMacros`), тут —
  лише як. Ключ дати розбирає `dateKeyParts` ядра.
- `formatMoment`: `timestamptz` у SQLite — текст у двох формах (пристрій — ISO,
  реплікація — з пробілом); нечитане — порожній рядок, а не вигадана дата.
- `meal-text.ts` нічого не добудовує: без кількості — без `amount`/`unit`;
  порція, що не розкладається за Ж/Ч, — текстом дослівно
  (`portionForLetter` → `null`). «Ж — 130 г» — текст порції, а не складник «Ж».

## calendar-search.ts, meals-search.ts

Невідоме значення з адреси — «без параметра»; дата мусить існувати (30
лютого відкидається), тиждень вирівнюється на понеділок. Правила — у тестах.

## shopping-share.ts

Текст — той самий список, що на екрані: лише некуплене, кількість лише з
джерела, позиції без неї окремим блоком. Порожній текст — кнопки немає.

## scroll-catch-up.ts

`catchUpScroll` докручує, щойно документ виростає, доки не досягне цілі (з
допуском 1 px). Відступає на `pointerdown`/`keydown`/`wheel` (не `scroll`: його
викликає й наш `scrollTo`) або коли позиція вища за нашу й не внизу — людина
гортає смугою. Правила — у `scroll-catch-up.test.ts`.

## day-clock.ts

**Вікна прийомів їжі — налаштування сім'ї, а не правило дієтолога**, тому
живуть тут, а не в `packages/core`. Сім'я задає сніданок, обід і вечерю
(`MealHours`, MER-114) — одні на всіх, синхронізуються через `family_settings`;
без налаштування діють `DEFAULT_MEAL_HOURS` із V1. Перекус — завжди проміжок
між кінцем обіду й початком вечері; обід упритул до вечері лишає перекус без
вікна. З тих самих вікон `slotAt` бере фазу неба (`components/Sky.tsx`),
активну страву на «Сьогодні» і розклад нагадувань, тож функції приймають
вікна аргументом, а не беруть константу.

- **Валідація одна — `mealHoursProblems`**: її показує форма біля поля, нею ж
  `mealHoursFromRow` відкидає битий рядок (тоді діють стандартні вікна, а
  екран показує попередження). Ті самі межі тримають CHECK-и бази.
- `MealWindow` не має підпису: назва прийому — `MEAL_TYPE_LABELS` ядра, другий
  примірник розійшовся б із першим.
- **`useMealWindows` працює й без бази**: поза `MealWindowsProvider` або до
  відкриття локальної бази (екран входу) — стандартні вікна.


## reminders.ts

Порт нагадувань V1 на веб (MER-65). Такт і налаштування —
`components/Reminders.tsx`.

- **Налаштування — стан ПРИСТРОЮ, і в синхронізацію не їдуть** (рішення
  MER-55): телефон і ноутбук мають різні режими сповіщень, а дозвіл на
  сповіщення видається кожному пристрою окремо.
- **Розклад дає годинник дня, а страву до тексту — план активного профілю.**
  Плану на слот немає — так і кажемо: страву не вигадуємо.
- **Такт живе в `AppGate`, а не на екрані «Сьогодні»**: нагадування мають
  приходити й тоді, коли відкрито інший екран. Свого таймера немає — такт дає
  `useNow`.
- **Сервера пушів немає.** Сповіщення шле сама сторінка, поки застосунок
  відкритий, і саме це написано в інтерфейсі. Пропущене «доганяємо» лише в
  межах `CATCH_UP_MINUTES` (браузер присипляє фонові таймери).
- **Вимкнення прибирає й показане** (`closeReminders`): сповіщення з тегом
  висить, доки його не закриють. Показані без воркера тримаються в списку —
  реєстрація бачить лише свої.
- Випередження за північ стискається до 00:00 тієї самої доби; тег один на
  слот і добу; позначки надісланого — лише за поточну добу.
- **Відмова в дозволі — не аварія.** `notificationState()` окремо розрізняє
  «браузер не вміє» і «заблоковано», екран каже це прямо, а такт мовчить.
- **Показ — через воркер, коли той керує сторінкою.** Лише так сповіщення
  доживає до згорнутого застосунку, а на Android конструктор `Notification`
  заборонений зовсім. Питати `navigator.serviceWorker.ready` без контролера не
  можна — обіцянка не розв'яжеться ніколи. Клік по сповіщенню обробляє воркер
  (`notificationclick` у `public/sw.js`).

## starter-set.ts

Клієнтська частина стартового набору (MER-77). Формат файлу й правила засіву
для сім'ї — у
[`packages/core/README.md`](../../../../packages/core/README.md#як-засівається),
підключення на сервері — в `infra/README.md`. Тут лише те, що стосується
пристрою:

- **Автозасів — лише після першої синхронізації.** До неї пул пристрою
  порожній, хоч що лежить на сервері, тож рішення до неї переписало б правки
  сім'ї. Порядок кроків — `autoSeed` (там і тести); сам засів — звичайні
  записи в локальну базу (`seedStarterMeals`), а `claim_starter_set` — після
  них.
- «Засіяно» пристрій кешує в `localStorage` за familyId і сервер більше не
  питає.
- **Позначка — після запису** (`markSeeded`): збій між ними лишає страви без
  позначки, і наступне відкриття її поставить; навпаки сім'я лишилась би ні з
  чим. `claim` → `false` (позначив інший пристрій) — засіяно однаково. Порядок
  і зупинки на виході з сім'ї — у `starter-set.test.ts`.
- Непорожній пул (страви до появи набору) — лише позначка, без запису; уже
  засіяна сім'я нових страв з оновленого файлу сама не отримує. Порожній чи
  зіпсований набір засів не «спалює».
- Кнопка «Додати стартовий набір» рахує відсутні серед живих страв пулу
  (`missingStarterMeals`).

## wake-lock.ts

`keepScreenAwake` тримає екран увімкненим через Screen Wake Lock API; правила
— у `wake-lock.test.ts`.

- **Браузер сам знімає блокування, щойно сторінку сховали** (згорнули
  застосунок, переключили вкладку), тож повернення на сторінку просить його
  знову. Без цього перемикач лишався б «увімкненим», а екран гаснув би.
- Відмова браузера (режим енергозбереження, політика дозволів) — не виняток, а
  `onError`: екран мусить сказати, що не вийшло, а не вдавати увімкнене.
- API є лише в захищеному контексті: на `http://` перемикача немає
  (`canKeepScreenAwake`).

## pdf-text.ts

- **pdf.js вантажиться лише динамічно** — з обробника події: у ньому воркер, а
  ~800 КБ у стартовому чанку заради дії раз на два тижні платити нема за що.
  Воркер береться зі збірки (`?url`), а не з CDN, інакше офлайн-застосунок
  мовчки перестав би читати PDF.
- **Необов'язкова залежність `@napi-rs/canvas` вимкнена** в
  `pnpm-workspace.yaml` (`ignoredOptionalDependencies`): це рендер сторінок у
  Node, 37 МБ нативного бінарника, а потрібен лише текстовий шар у браузері.
- Текст — рядками за `hasEOL`, як його чекає `parsePlanText`; документ у
  воркері закривається (`destroy`) і після скасування — PDF важить мегабайти.
- **`pdfjs-dist` оновлювати, а не відкладати.** Файл приносить користувач із
  пошти. `isEvalSupported: false` із V1 сюди не переїхав: це був обхід
  CVE-2024-4367 для старої версії, у 6.x прапорця немає, бо прибрали сам шлях
  зі `Function`.

## Відомі стелі (ponytail)

- **Перший кадр неба — за стандартними вікнами** (`applySky` у `main.tsx`):
  налаштування сім'ї лежать у локальній базі, яка відкривається пізніше. Якщо
  власні межі відрізняють фазу саме зараз, небо перемикається, щойно база
  відкриється. Апгрейд — дзеркало вікон у `localStorage` для першого кадру.
- **Стартовий набір кешується до перезавантаження** (`loaded` у
  `starter-set.ts`): набір один на сервер і міняється рідко. Новий файл видно
  після перезавантаження сторінки.
- **Наздоганяння прокрутки — 5 с від монтування** (`catchUpScroll`): локальна
  база відповідає за десятки мілісекунд. Повільніший телефон — підняти
  `timeoutMs`.
